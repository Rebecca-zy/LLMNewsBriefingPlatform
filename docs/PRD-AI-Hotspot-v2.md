# AI热点推送系统 - 需求文档（V3）

## 1. 需求背景与痛点
### 1.1 为什么要做
AI 资讯更新频率极高，人工整理存在明显时滞。业务团队需要一套自动化系统，把分散资讯转化为结构化、可落地的热点简报，并稳定触达到企业微信。

### 1.2 关键痛点
1. 来源分散，人工汇总成本高。
2. 英文内容占比高，阅读门槛高。
3. 对业务场景映射弱，难快速判断可用性。
4. 触达链路不稳定，历史沉淀不完整。

### 1.3 产品目标
1. 自动抓取 RSS 并生成中文热点简报。
2. 每 3 小时更新一次。
3. 按自然日倒序展示，当日只展示最新版本。
4. 支持企业微信群机器人推送。
5. 面向客户展示的详情页风格（非内部后台）。

## 2. 产品范围
### 2.1 网页端（对客展示）
1. 展示“当日简报”及历史日期切换。
2. 热点条目展示：标题、应用领域标签、中文简介、影响解读、原文链接。
3. 展示趋势摘要与基础元信息（更新时间、来源、触达渠道）。
4. 保留操作：更新简报、推送企业微信、分享链接。

### 2.2 推送端（企业微信）
1. 支持通过 webhook 推送简报。
2. 推送内容自动长度控制（避免 markdown 4096 超限）。
3. webhook 支持多种输入（完整 URL / key / webhook=URL）。

### 2.3 非范围
1. 运营后台配置页面（源配置、规则配置不在 UI 暴露）。
2. 审核流、多角色权限。
3. 多渠道并发推送编排。

## 3. 业务规则
### 3.1 定时规则
1. 调度周期：每 3 小时执行（00:00/03:00/06:00/.../21:00）。
2. 执行链路：抓取 -> 解析 -> 翻译/归纳 -> 应用领域推断 -> 生成简报 -> 推送。

### 3.2 简报版本规则
1. 每自然日只保留 1 条对外展示记录（最新版本）。
2. 页面日期按自然日倒序展示。
3. 同日多次运行以最新内容覆盖展示。

### 3.3 内容规则
1. 对客页面默认中文简介。
2. 影响解读必须包含“适用应用领域”。
3. 不展示评分文案（如“综合评分”）。
4. 保留来源链接，便于事实回溯。

## 4. 交互说明（当前实现）
1. 打开页面后默认加载最近一条简报。
2. 点击日期胶囊可切换历史简报。
3. 点击“更新简报”触发生成。
4. 点击“订阅企业微信推送”推送当前简报。
5. 点击“分享链接”复制页面地址。

## 5. 验收标准
1. 页面在桌面/平板/手机均可用（断点：1024/768/480）。
2. 生成、切换、推送、分享功能保持可用。
3. 企业微信推送在长度受控后不再触发 40058。
4. 样式符合对客展示定位：简洁、科技感、可读性优先。
